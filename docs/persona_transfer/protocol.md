# 疑似人格のモデル間保存：検証プロトコル v0.1

作成日：2026年10月2日
関連資料：「LLM間におけるペルソナベクトル移植の可能性」「他AI回答の検証：ペルソナベクトルのモデル間移植」
実装：`persona_xfer/`（実験・解析）、`configs/persona/`（設定）、`tests/test_persona_xfer.py`（検算）

## 0. このプロトコルの位置づけ

前の2つの報告書の結論は、次の3点に整理できる。

1. ペルソナベクトルの「数値列」はそのまま別モデルに移せない。表現空間の間の写像を学習すれば、個々の性格特性は移せる例がある。
2. 移植の成否を測る基準（同一人物性の操作的定義）が、どの先行研究にもない。
3. 最も価値のある問いは「人格を運ぶ層はテキストで足りるのか、ベクトルが要るのか」を比較実験で切り分けることである。

本プロトコルは、この3点を実験として検証できる形に落とす。とくに次の3つを最初から組み込む。

- 報告書で欠けていると指摘したベースライン（再抽出・プロンプトのみ・検索）
- 「保存された」と言うための事前登録の判定基準
- 線形ベクトルの限界（条件付きの判断規則）を直接測る項目

## 1. 研究課題

**主問：** 同じ人格定義を与えたとき、異なる LLM の間でその人格は「同じ人物」として保たれるか。保たれるなら、どの経路でどこまで保たれるか。

| 番号 | 問い | 対応する比較 |
|---|---|---|
| RQ1 | テキスト（自己記述・判断記録）だけで、人格はモデルをまたいで保たれるか | prompt / retrieval と base の比較。モデル間の同一性行列 |
| RQ2 | 写像で移植した人物ベクトルは、移植先で再抽出したベクトルと同等に働くか | steer_transfer と steer_native（非劣性）、steer_random（優越） |
| RQ3 | ベクトルはテキストに上乗せの価値を持つか（PAP の製品設計上の問い） | retrieval+steer_native と retrieval |
| RQ4 | 固定ベクトルは、状況によって答えが変わる「条件付き判断」を表せるか | 規則依存項目と非依存項目での、ステアリングとテキストの差（交互作用） |
| RQ5 | 活性化に触れないフロンティアモデルでも、テキスト経路で同じ人格が再現されるか | API モデルを含めたモデル間の同一性行列 |

## 2. 操作的定義

### 2.1 疑似人格＝モデルに依存しない「定義データ」

人格は、モデルの重みや活性化ではなく、次の定義データとして持つ。報告書の結論「持ち運ぶべきはベクトルではなく定義」に対応する。

| 層 | PAP の構成要素 | 本実験での形 |
|---|---|---|
| 深層（価値） | SelfModel の中核 | 8つの価値の重み（家族・誠実・挑戦・安定・思いやり・達成・自律・伝統）。モデルには自然文の自己記述として渡す |
| 中間（判断規則） | SelfModel の規則・DecisionRecord | 文脈（仕事か私生活か、相手、損失の大きさ）に応じて価値の重みを変える規則。過去の判断記録（状況・選択・理由） |
| 表層（気質・話し方） | SelfModel の表層 | Big Five の目標プロフィールと話し方の記述 |

パイロットでは架空の4人物（`persona_xfer/data/personas.json`）を使う。真の回答は「重み＋規則」から決定的に計算するので、項目ごとに正解がある。

### 2.2 人格が「保存された」の定義

移植先モデル B の条件 X について、次の5つをすべて満たすとき「保存された」と判定する。数値は事前登録値で、Phase 1 の結果を見て Phase 2 の開始前に一度だけ見直せる（§8）。

| 基準 | 指標 | 閾値（暫定） | 意味 |
|---|---|---|---|
| C1 上積み | 判断一致率の base との差 | +0.10 以上、かつ 95% CI の下限が 0 より上 | 人格を与えたことで、その人の判断に寄った |
| C2 識別 | 20項目の回答から4人のうち本人を最尤で当てる率 | 0.80 以上（チャンスは 0.25） | 他の人物と取り違えられない |
| C3 気質 | Big Five プロフィールと目標の相関 | 0.60 以上 | 表層の気質も再現された |
| C4 能力保持 | 中立文のパープレキシティ比（ステアリング時のみ） | 1.10 以下 | 人格を入れてもモデルが壊れていない |
| C5 モデル間同一性 | 異なるモデル間で、同じ人物の「判断の動き」の相関が他の人物との相関を上回る量 | 0.20 以上 | 人格がモデルをまたいで同じ形で現れる |

C5 が本研究の中心指標である。各モデルで「人物を与えたことによる判断の動き」Δ = P(B | 条件) − P(B | base) を項目ごとに求め、モデル1 の人物 p とモデル2 の人物 q の Δ の相関を 4×4 の行列にする。対角（同じ人物）が非対角より高いほど、モデル固有の癖を差し引いたうえで同じ人格が現れている。base を引くのは、モデルごとの「無難な答えへの偏り」を同一性と取り違えないためである。

## 3. 実験計画

### 3.1 要因

モデル × 条件 × 人物 × 項目の完全交差。判断項目は 47 場面・65 項目である。そのうち 18 場面は、文脈だけが違う2項目の対になっている。

| 条件 | 中身 | 役割 |
|---|---|---|
| base | 中立のシステムプロンプト | 下限。モデル固有の偏りの基準 |
| prompt | 自己記述（3層）をシステムプロンプトに入れる | テキスト経路の最小形 |
| retrieval | 自己記述＋質問に近い過去の判断記録4件 | PAP の比較条件1（検索ベースライン） |
| steer_native | 移植先で抽出し直した人物ベクトルを加算 | ベクトル経路の上限（「再抽出」） |
| steer_transfer:元 | 元モデルの人物ベクトルを写像して加算 | 本来の「移植」 |
| steer_random | steer_native と同じ大きさのランダム方向 | 陰性対照 |
| retrieval+steer_native | 検索プロンプト＋人物ベクトル | ベクトルの上積みの検定（RQ3） |

フロンティアモデル（Claude など）は base / prompt / retrieval だけを実行する。活性化に触れられないためで、報告書 4.3 の構造（Frontier 側への人格の伝達はテキスト経由）をそのまま実験の構造にしている。

### 3.2 モデル対の距離

写像の難しさはモデル間の距離で変わる（報告書の表）。そのため移植の対を距離別に組む。

| 距離 | 対の例（`configs/persona/main_7b.json`） | 先行研究との関係 |
|---|---|---|
| 同系列・サイズ違い | Qwen2.5-3B → Qwen2.5-7B | Model Stitching（同一ファミリー限定）の再現 |
| 異系列・同規模 | Llama-3.1-8B ↔ Qwen2.5-7B、Qwen → Mistral、Llama → Gemma | Cross-Architecture Steering Transfer の再現と、人格単位への拡張 |
| 活性化なし | Claude（API）とオープンモデル | テキスト経路のみ |

### 3.3 手続き

1. **分割：** 場面単位で 40% を学習用、60% を評価用に分ける（`split_seed=0`）。文脈違いの対は同じ側に入る。学習用は、判断記録の作成と、層・α の調整だけに使う。判定はすべて評価用で行う。
2. **判断の採点：** 「A か B の1文字で答えて」と指示し、次のトークンが A / B である対数確率を読む。選択肢の順番を入れ替えた2通りを必ず測って平均する（位置バイアスの相殺）。生成は行わない（決定的で安い）。
3. **人物ベクトルの抽出：** 抽出用の中立な30問（評価項目と重複しない）を使い、各層の最後のトークンの活性化について「人物ありのシステムプロンプト − 中立」の平均差を取る。全層分をキャッシュする。
4. **写像：** 人物を含まない対応テキスト（汎用の役割24種＋中立 × 写像用の30問 = 750 対）で両モデルの活性化を取る。それを使い、層 ℓ_A → ℓ_B（同じ相対深さ）のリッジ回帰写像を5分割交差検証で学習する。評価対象の4人物の情報は写像に入らない。写像後のベクトルは、人物を含まないコーパスの尺度比で大きさを補正する（移植先の人物ベクトルは使わない）。
5. **調整：** 層（相対深さ 0.25〜0.75）と α の格子を、すべてのステアリング条件で同じ予算で探索する。基準は学習用項目の平均 P(正解) とし、選んだ値で評価用を一度だけ採点する。選んだ値が格子の端なら報告書に警告が出る。
6. **付随測定：** Big Five（Mini-IPIP 20項目の試訳。1〜5の確率から期待値を計算）、中立文の NLL、写像の診断（移植ベクトルと再抽出ベクトルのコサイン類似度、写像の交差検証 R²）、回答形式の遵守（A/B に乗った確率の合計）。

## 4. 仮説と検定（事前登録）

| 仮説 | 内容 | 検定 |
|---|---|---|
| H1 | prompt・retrieval の一致率は base より高い（各モデル） | 対応のある差、場面単位の符号反転並べ替え（片側） |
| H2a | steer_transfer > steer_random | 同上 |
| H2b | steer_transfer は steer_native に対して非劣性（δ = 0.05） | 差の 90% CI の下限 > −δ |
| H3a | retrieval+steer_native > retrieval | 並べ替え（片側） |
| H3b | steer_native と retrieval の差（探索的） | 並べ替え（両側） |
| H4 | 規則依存項目では、ステアリングのテキストに対する不利がより大きい | 交互作用（retrieval − steer_native の差が規則依存項目で大きい）、場面単位ブートストラップ |

- 有意水準は 0.05 とする。H1・H2a・H3a・H4 を確認的検定の族として Holm 補正する。
- 主要指標は二値の一致（P(正解) > 0.5）である。副次指標は P(正解) の平均とする。
- 同じ場面の文脈違いの項目と、同じ項目に対する4人物の行は独立でない。そのため、再標本化・並べ替えの単位はすべて場面にする。
- **H3a が棄却されない（ベクトルの上積みがない）こと自体が、PAP の設計判断にとって重要な結果である。** 報告書の「人格を運ぶ層はテキストで足りるのではないか」という反論を支持するからである。結果がどちらでも報告する。

## 5. バイアスへの対策

| 想定される偏り | 対策 |
|---|---|
| 選択肢の位置の偏り | 順番を入れ替えた2通りの平均 |
| 条件ごとの調整量の差 | 層・α は全条件で同じ格子・同じ学習用項目で選ぶ |
| 調整の過適合 | 場面単位で分けた評価用だけで判定する。層・α は全人物で共通の1組 |
| 写像への人物情報の漏れ | 写像は人物を含まないコーパスだけで学習する。大きさの補正にも移植先の人物ベクトルは使わない |
| モデル固有の「無難な答え」 | C5 は base からの差 Δ で測る。C1 は base との対比較 |
| ステアリングがモデルを壊して見かけの効果が出る | ランダム方向の対照、パープレキシティ比、A/B のラベル確率 |
| 形式に従えない小型モデル | ラベル確率が低い条件は解釈から外す（報告書に表示） |
| 偶然の一致 | 4人物の識別率（チャンス 0.25）。ランダム方向の同一性行列 |

## 6. 妥当性への脅威（既知の限界）

1. **架空人物はテキストで定義されている。** 真の回答は自己記述にある規則から計算されるので、テキスト条件に有利な設計である。この偏りは、実在の人物の判断データで真値を取る Phase 3 で解消する。パイロットの「テキストがベクトルに勝つ」は、そのまま実在人物には一般化しない。
2. **人物ベクトルはプロンプト末尾の活性化から取る。** 元論文は応答トークンの平均を使っている。生成を省いた簡略版で、応答トークン版は拡張として残す（§9）。
3. **二択の判断は、自由な語りの人格を測らない。** 話し方・文体・価値の語り方は、Phase 4 の生成課題（本人・家族による識別）で扱う。
4. **API モデルは対数確率が取れない。** 1文字の回答を2通りの順番で取るため、1項目あたり 0 / 0.5 / 1 の3値になり、オープンモデルより粗い。必要なら `n_samples` を増やす（費用が比例して増える）。
5. **Mini-IPIP の日本語は試訳で、妥当性検証を経ていない。** C3 は参考指標として扱い、正式な尺度が必要なら検証済みの日本語版に差し替える。
6. **小型モデルの日本語能力。** 形式の遵守率（ラベル確率）で監視する。必要なら英語版の項目バンクを作る。
7. **検出力が小さい（§7）。** パイロットの評価用は39項目で、規則依存項目は人物あたり5〜8項目しかない。H4 の検定はパイロットでは探索的扱いとする。

## 7. 検出力の見積もり

対応のある二値差の標準誤差は、おおよそ √(不一致率 / n) × クラスタ補正で決まる。不一致率 0.3、クラスタ補正 1.2 とすると、検出できる最小の差は次のとおり。

| 規模 | 評価観測数（人物×項目） | 検出可能な最小差（80% 検出力、Holm 後） |
|---|---|---|
| パイロット（現行の項目バンク） | 約150 | 約0.13（補正なし）〜0.20（Holm で最も厳しい順位） |
| 本実験の推奨（120場面、8人物） | 約1,400 | 約0.04〜0.06 |

**推奨：** Phase 2 の前に、項目バンクを120場面（文脈違いの対を40対以上）に、人物を8人に増やす。

Phase 0 では、ランダム方向の対照の「モデル間同一性」が 0.19（95% CI 0.08–0.31）と、閾値 0.20 のすぐ下に出た。4人物では、1回のランダム方向でも偶然に見かけの同一性が出うる。対策は2つある。

- ランダム方向の乱数種を5つ以上にして、帰無分布として使う。
- 人物を8人以上にする。

### Phase 3 のデータ収集（実在人物）

1. 本人が判断項目（120場面以上）に回答し、各回答に一文の理由を付ける。これが DecisionRecord になる。
2. **2週間後に同じ項目へ再回答してもらう。** 本人の再現率（再検査一致率）が、どのモデルも超えられない上限（ノイズの天井）になる。判定基準 C1 は、この天井に対する比率でも報告する。
3. SelfModel（深層・中間・表層の自己記述）は、判断項目に答える**前に**書いてもらう。後で書くと、項目への回答が記述に漏れる。
4. **識別テスト：** 評価用の場面について、本人の回答・理由と、モデルが生成した回答・理由を対にして、本人と家族が盲検で「どちらが本人か」を当てる。正答率がチャンス（0.5）と区別できないことを、同等性検定（例：±0.1）で示せれば、外部基準での保存と言える。
5. **倫理：** 研究目的・データの保管と削除・モデルへの入力範囲について、本人と家族の書面同意を取る。故人の人格の再現は対象外とする。

## 9. 実行方法

```bash
pip install -r requirements.txt               # 実モデルには torch / transformers も必要
python -m pytest -q tests                      # 検算（Phase 0 の陰性・陽性対照を含む）
python scripts/persona_run.py configs/persona/toy_pilot.json      # 合成モデルでの較正（CPU で約2分）
python scripts/persona_run.py configs/persona/pilot_small.json    # Phase 1（GPU、Hugging Face への接続が必要）
python scripts/persona_run.py configs/persona/pilot_small.json --analyze-only   # 報告書だけ作り直す
```

- 結果は `results/persona/<名前>/` に出る。`report.md`（報告書）、`tables/*.csv`（数値）、`figures/`（PNG と PDF）。
- 実行はモデル単位で途中から再開できる。`--force` を付けると最初からやり直す。
- Claude を使う条件では、`ANTHROPIC_API_KEY` などの認証が必要。拒否された回答は欠測として扱い、別モデルへのフォールバックは使わない（別のモデルの回答が混ざると測定が成り立たないため）。

## 10. Phase 0 の結果（合成モデル。科学的知見ではない）

合成モデルには、次の効果を構成上与えてある。

- 人物ベクトルは写像で移せる。
- ステアリングは条件付き規則を表せない。
- テキストは規則を表せる。

解析がこれらを正しく取り出せるかを見た結果は次のとおり（`results/persona/toy_pilot/report.md`）。

| 確認したこと | 結果 |
|---|---|
| テキスト条件の効果（H1） | base 0.50〜0.54 → prompt 0.80〜0.90。全モデルで p_holm = 0.003 |
| 移植 > ランダム（H2a） | 差 +0.17〜+0.31。p_holm ≤ 0.013 |
